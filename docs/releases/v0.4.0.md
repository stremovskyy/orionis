# Orionis v0.4.0

Orionis 0.4.0 is a compatibility-preserving internal refactor focused on
simpler package boundaries, predictable configuration, safer concurrency, and
repeatable release verification.

## Highlights

- Split the core, client, JWK, server, Gin, and standalone runtime into focused
  files while keeping the exported API compatible with `v0.3.2`.
- Unified builder and config entry points around one defaults and validation
  path per package.
- Hardened client token caching with request coalescing, isolated waiter
  cancellation, input copying, and expired-entry cleanup.
- Unified static and remote JWK decoding, strengthened key metadata validation,
  and coalesced remote refreshes for first use, expiry, and unknown key IDs.
- Separated OAuth HTTP parsing from token issuance, isolated memory-store
  values, validated static clients and signer sets, and preserved live signer
  key publication.
- Added compatible `/readyz` mounting and `ReadyPath` support while preserving
  existing Gin middleware flow and custom route ownership.
- Reworked standalone startup into decode, normalize, validate, load, and build
  phases so invalid configuration is rejected before key creation.
- Added bounded JSON decoding, expanded contract and concurrency tests, API
  compatibility checks, coverage gates, and one canonical verification target.

## Security and operations

- Raise the module minimum and image build toolchain to Go `1.25.14`.
- Updated `golang.org/x/crypto`, `golang.org/x/net`, `golang.org/x/sys`, and
  `golang.org/x/text` to patched releases.
- Refresh Alpine packages during the runtime image build.
- Validate the standalone image, discovery document, JWKS rotation set,
  readiness endpoint, token issuance, and a protected service request before
  publishing release images.
- Publish SBOM and provenance attestations for Docker Hub and GHCR images.

## Compatibility

- Exported Go APIs remain source-compatible with `v0.3.2`; exact duplicate
  entry points remain available as deprecated wrappers.
- Existing JSON configuration fields, legacy single-key configuration,
  multi-key rotation, OAuth responses, JWT claims, wildcard scopes, cache
  defaults, and endpoint paths remain supported.
- `/healthz` and `/readyz` intentionally return the same payload in this
  release.

## Upgrade

```bash
go get github.com/stremovskyy/orionis@v0.4.0
```

Container images are published as:

```text
stremovskyy/orionis:0.4.0
ghcr.io/stremovskyy/orionis:0.4.0
```

Run the complete local release gate with:

```bash
make verify
```

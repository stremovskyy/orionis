01

Three roles. One clear trust model.

Orionis implements OAuth 2.0 client credentials: a service proves its own identity to call another service.

CALLER

Ask for access.

The orders service authenticates with its client ID and secret. It requests a token for billing and the actions it needs.

AUTHORIZATION SERVER

Grant and sign.

Orionis checks the caller’s grants, signs a short-lived JWT, and publishes the corresponding public keys through JWKS.

RESOURCE SERVICE

Verify and serve.

Billing checks the signature, issuer, audience, time claims, token use, and route permissions before running the handler.

Caller
The service making a request, identified by its client ID.
Audience
The API a token is intended for, such as billing-api.
Scope
A permission, such as billing.invoice.create.
JWT
A signed token carrying the service identity, target, permissions, and expiry.
JWKS
The public key set used to check token signatures.
GIN guard
Middleware that verifies tokens and enforces route scopes.
02

Your first authorized request.

Run the included orders → billing example in three terminals. The caller obtains and attaches the token for you.

Start with the source.

Use Go 1.26 or newer. Clone the repository, then run each command from its root directory.

Set up the example
git clone https://github.com/stremovskyy/orionis.git
cd orionis
git checkout v0.6.0
Local development

The example uses HTTP, demo credentials, and file-backed signing keys. Follow the deployment guide before running in a shared environment.

Prefer containers? Use the Docker and Compose guide. Java and PHP callers are also included in the examples directory.

TERMINAL 01Start Orionis

Shell · authorization server 
go run ./cmd/orionis-auth -config ./config/orionis.example.yaml

TERMINAL 02Start the protected API

Shell · billing API
go run ./examples/gin-billing-service

TERMINAL 03Make the request

Shell · orders caller 
go run ./examples/gin-orders-client

status=201Invoice created by orders-service.

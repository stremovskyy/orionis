# Orionis v0.7.0

YAML is now the default local and Docker configuration format. The v0.7.0
image looks for `config/orionis.yaml`, `config/orionis.yml`, then the legacy
`config/orionis.json`. When running from a source checkout without a personal
config, it selects `config/orionis.example.yaml` before the JSON example.
An existing personal JSON config therefore wins over the bundled YAML example.

- `-config` takes priority over `ORIONIS_CONFIG`; both still accept a JSON file
  or `-config aws`. Explicit paths never trigger automatic fallback.
- An invalid or unreadable selected YAML file stops startup instead of
  silently loading JSON. There is no schema, OAuth API, or token change.
- AWS AppConfig continues to detect YAML and JSON from content. The ECS guide
  now leads with a YAML example and retains its JSON example for existing
  deployments.
- JSON-only Docker installations keep starting without a command change.
  New installations should use `config/orionis.yaml`.
- The build and verification toolchain is Go 1.26.11, which includes the
  November 2026 `net/http` security fix.

To run the source example explicitly:

```bash
go run ./cmd/orionis-auth -config ./config/orionis.example.yaml
```

Images: `stremovskyy/orionis:0.7.0` and
`ghcr.io/stremovskyy/orionis:0.7.0`.
